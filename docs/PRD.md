## 1. 背景

一家擁有約 40 艘船（鮪魚圍網船＋冷凍運搬船）的遠洋漁業公司，主要在西／中太平洋熱帶海域（PNA 國家海域）作業，正從 0 開始建資訊平台。
目前的問題：船位（VMS）、集魚器（FAD）浮標、海況、漁獲日誌、油耗、合規期限散在不同系統與 Excel，管理層沒有一個畫面能看到全局。

PELAGOS 是這個平台的第一期雛形：**以地圖為核心，把海況、船隊、航次、浮標與事件放在同一個畫面上，讓管理者一眼看懂並做決定。**

**我們沒有漁業實務經驗。** 本 PRD 的功能分成「業界實務」、「推測」、「純展示」三種依據（見 §5），展示時以「這是我的假設，請你們指正」的立場呈現。

## 2. 目標與非目標

**目標**
- G1 管理者 5 秒內回答：「我的船在哪？誰有狀況？這一趟發生了什麼？」
- G2 同一畫面流暢呈現**上萬個移動點**（船＋浮標）加洋流動畫
- G3 視覺有指揮中心的科技感，但資訊易讀
- G4 每個技術決定都能說明理由（README「技術決策」）
- G5 資料模型能直接延伸成正式產品（換後端不用改畫面）

**非目標（v2 不做）**
- 後端、資料庫、登入權限（資料層先設計成可替換的介面；正式架構見 §9）
- 真實 AIS／VMS／浮標平台串接
- 手機版（P2）

## 3. 使用者

| 角色 | 在哪 | 要什麼 |
|---|---|---|
| 營運主管 | 高雄岸上辦公室 | 全船隊狀態、異常警示、合規期限 |

| 經營者 | 會議室大螢幕 | 一頁看懂的 KPI |

## 4. 核心資料模型（借用 HIS 的骨架）

HIS 的核心是「管理病人＋管理病程」；船隊系統的核心是「**管理船＋管理航次**」。地圖只是這個模型的其中一個視圖。

| HIS | PELAGOS | 欄位（模擬資料照此產生） |
|---|---|---|
| 病人主檔 | **Vessel 船舶** | id、船名、類型（圍網／運搬）、船籍、所屬公司 |
| 住院（Encounter） | **Trip 航次** | id、vesselId、出港時間、出港港口、狀態（進行中／已返港） |
| 病程紀錄 | **Event 事件**（依時間排列） | tripId、時間、類型、位置、內容 |
| 醫囑、處置 | 事件類型 | 出港、航行、下網（每網一筆，附漁獲噸數）、放浮標、轉載、靠港、加油 |
| 生命徵象 | **Position 船位回報** | vesselId、時間、經緯度、航速、航向（模擬 VMS，每小時一點） |
| 檢驗儀器 | **Buoy 浮標回報** | buoyId、vesselId、時間、位置、估計魚量（噸） |
| 早警分數 | **Alert 警示** | 由規則從上述資料推導（訊號中斷、油料低、禁用期…） |
| 出院摘要 | **航次摘要** | 航次天數、下網次數、累計漁獲、油料剩餘 |

資料交換標準的對照：HIS 有 HL7／FHIR，漁業有 **UN/CEFACT FLUX**（歐盟電子漁獲日誌強制使用）。v2 不實作，README 提及。

## 5. 資料

| 資料 | 來源 | 真實／模擬 | 檔案 |
|---|---|---|---|
| 底圖 | CARTO Dark Matter 向量圖磚 | 真實 | 線上 |
| 海溫、海溫異常 | NOAA OISST v2.1（ERDDAP） | 真實 | `public/data/sst.json`、`sst.png`、`sst_anom.png` |
| 洋流 | NOAA NESDIS 地轉流 ugos／vgos（ERDDAP） | 真實 | `public/data/currents.json` |
| 自家船隊與航次 | 30 艘圍網船＋6 艘運搬船，每艘一個進行中航次與事件 | 模擬 | 前端以固定亂數種子產生 |
| 周邊船隻 | 1 萬～10 萬艘，可切換（**壓力測試，非實際船數**） | 模擬 | Web Worker 產生 |
| FAD 浮標 | 約 1 萬個（每船上限 350，WCPFC 規範），附估計魚量 | 模擬 | 前端產生，隨洋流漂移 |
| 海況熱區 | 由海溫鋒面＋洋流算出的示意分數（**不是預測模型**） | 示意 | 前端計算 |

**範圍**：東經 100° → 西經 150°（跨國際換日線，內部經度一律用 0–360）、南緯 20° → 北緯 45°。
**原則**：模擬資料只出現在海上（用海溫網格當陸地遮罩）；每個圖層標示來源與資料時間；模擬資料明確標「模擬」。

## 7. 非功能需求

| 項目 | 目標 |
|---|---|
| 效能 | 桌機：5 萬點 ≥ 55 FPS、10 萬點 ≥ 30 FPS；模擬不在主執行緒 |
| 載入 | 首次可互動 < 3 秒（資料檔總和 < 1 MB） |
| 穩定 | 任一資料檔載入失敗，其他圖層照常並顯示提示 |
| 程式 | TypeScript strict；單檔 < 300 行；一個圖層一個檔案 |
| 部署 | GitHub Pages（公開 repo），push main 自動部署 |

## 8. 視覺規範

- 深色底；介面近單色＋**單一重點色青色**；警示紅、注意琥珀。資料本身（海溫色階）不受此限
- 數字一律等寬字體；面板用細線框與四角標記，不用大面積霓虹與陰影
- 不用 emoji，圖示一律 inline SVG
- 介面中文，欄位可加小字英文（例：航速 SOG）

## 9. 技術架構

### 現行（demo）

```
NOAA ──Python ETL──► public/data/*.json/png
                          │
               DataSource 介面（src/data）：Vessel / Trip / Event / Position / Buoy
                          │            └─ 之後換成 API，畫面不用改
   layers/  sst · anomaly · currents · fleet · buoys · trip-track · hotspot
   sim/     seed（船、航次、事件） · fleet.worker（周邊船位置）
                          │
   MapLibre 底圖 + deck.gl（MapboxOverlay）
                          │
   hud/     KPI · 詳情卡＋航次時間軸 · 警示流 · 回放 · 效能 · 圖層開關
   store.ts（Zustand）
```

### 正式產品（面試說明用，不實作）

```
[船上] VMS／儀器／浮標 ──► 船上資料中樞（Signal K 類，離線先存）
                                │ 衛星網路（貴、不穩：只傳差異）
[岸上] 收集服務 ──► PostgreSQL + PostGIS + MobilityDB（船、航次、事件、軌跡）
                                │
                   向量圖磚（martin）＋ API
                                │
                   PELAGOS 前端（MapLibre + deck.gl）
外部來源：浮標平台、電子漁獲日誌、iFIMS、海況（NOAA／Copernicus）；交換標準 FLUX
```

### 技術決策

| 決策 | 選擇 | 理由 |
|---|---|---|
| 底圖 | MapLibre | 開源、不需 token、無用量計費 |
| 大量圖層 | deck.gl | WebGL 批次繪製；Global Fishing Watch 的地圖也採用 deck.gl |
| 洋流 | Canvas 粒子拖尾 | 效果成熟（參考 cambecc/earth、mapbox/webgl-wind）、成本低 |
| 模擬 | Web Worker＋Float32Array | 主執行緒不卡；二進位傳輸免序列化 |
| 資料模型 | 船 → 航次 → 事件 | 對應業務流程；參考 HIS 的病人／病程，以及 Traccar 的裝置／位置／事件 |
| 狀態 | Zustand | 跨元件共用且避免全樹重繪 |
| 樣式 | CSS 變數＋CSS Modules | 細調線框與光暈 |
| 投影 | 麥卡托 | 地球儀投影與 deck.gl 的相容性未驗證，不冒險 |
| 資料 | 預先烘焙的靜態檔 | 無後端可部署；換 API 只改 DataSource |

## 10. 展示腳本（3–5 分鐘，「假設 → 請指正」）

1. 開機序列 → 「我沒做過漁業，所以先做了功課。這是我對你們需求的**假設**，公司是虛構的，海況是 NOAA 真實資料」
2. 海溫 → 異常 → 洋流：「我理解魚群跟著暖池邊緣走，對嗎？」
3. 浮標圖層 → 傾斜成 3D 光柱：「每艘船最多 350 個浮標，聲納會回報魚量。你們現在是看浮標廠商的平台嗎？」
4. 點一艘自家船 → 詳情卡＋航次時間軸：「我用 HIS 的方式設計：船是病人、航次是病程、每一網是一筆醫囑」
5. 效能 HUD 切到 10 萬：「這是壓力測試，實際船數沒這麼多。重點是為什麼還能跑：Worker、二進位、遠看聚合」
6. 回放＋警示流：「這些警示是我猜的，你們最在意的是哪些？」
7. 海況熱區：「這只是示意，你們的模型輸出會接在這層」
8. 收尾：正式架構圖＋「這個專案是 Claude 和 Codex 接力開發的，交接文件在 repo 裡」→ 接反問問題
