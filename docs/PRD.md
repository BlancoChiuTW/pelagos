# PELAGOS — 遠洋船隊戰情儀表板 PRD v1

> 版本：v1（2026-11-02）｜狀態：開發中｜展示期限：2026-11-03 12:00 凍結
> 公司與船名全部虛構（「藍潮漁業」）。海溫與洋流是 NOAA 真實資料，船隊與浮標是模擬資料。

## 1. 背景

一家擁有約 40 艘船（鮪魚圍網船＋冷凍運搬船）的遠洋漁業公司，主要在西／中太平洋熱帶海域（PNA 國家海域）作業，正從 0 開始建資訊平台。
目前的問題：船位、集魚器（FAD）浮標、海況、漁獲、油耗、合規期限散在不同系統與 Excel，管理層沒有一個畫面能看到全局。

PELAGOS 是這個平台的第一期雛形：**以地圖為核心，把海況、船隊、浮標與事件放在同一個畫面上，讓管理者一眼看懂並做決定。**

## 2. 目標與非目標

**目標**
- G1 管理者 5 秒內回答：「我的船在哪？誰有狀況？下一網該往哪？」
- G2 同一畫面流暢呈現**數萬個移動點**（船＋浮標）加洋流動畫
- G3 視覺有指揮中心的科技感，但資訊易讀
- G4 每個技術決定都能說明理由（寫在 README「技術決策」）

**非目標（v1 不做）**
- 後端、資料庫、登入權限（資料層先設計成可替換的介面）
- 真實 AIS／VMS 串接
- 手機版（P2）

## 3. 使用者

| 角色 | 在哪 | 要什麼 |
|---|---|---|
| 營運主管 | 高雄岸上辦公室 | 全船隊狀態、異常警示、合規期限 |
| 船隊調度／漁撈顧問 | 岸上 | 海況與魚群熱區，建議船往哪移 |
| 經營者 | 會議室大螢幕 | 一頁看懂的 KPI 與趨勢 |

## 4. 資料

| 資料 | 來源 | 真實／模擬 | 檔案 |
|---|---|---|---|
| 底圖 | CARTO Dark Matter 向量圖磚 | 真實 | 線上 |
| 海溫、海溫異常 | NOAA OISST v2.1（ERDDAP） | 真實 | `public/data/sst.json`、`sst.png` |
| 洋流 | NOAA NESDIS 地轉流 ugos／vgos（ERDDAP） | 真實 | `public/data/currents.json` |
| 自家船隊 | 30 艘圍網船＋6 艘運搬船 | 模擬 | 前端以固定亂數種子產生 |
| 周邊船隻 | 1 萬～10 萬艘，可切換 | 模擬 | Web Worker 產生 |
| FAD 浮標 | 約 1 萬個（每船上限 350），附估計魚量 | 模擬 | 前端產生，隨洋流漂移 |
| 漁場預測 | 由海溫鋒面＋洋流推算的示意分數 | 示意模型 | 前端計算 |

**範圍**：東經 100° → 西經 150°（跨國際換日線，內部經度一律用 0–360）、南緯 20° → 北緯 45°。
**原則**：所有模擬資料只出現在海上（用海溫網格當陸地遮罩）；畫面上每個圖層標示資料來源與時間。

## 5. 功能需求

優先序：**P0** 必做（沒有就不能展示）、**P1** 亮點、**P2** 有時間才做。

## 6. 非功能需求

| 項目 | 目標 |
|---|---|
| 效能 | 桌機：5 萬點 ≥ 55 FPS、10 萬點 ≥ 30 FPS；船隊模擬不在主執行緒 |
| 載入 | 首次可互動 < 3 秒（資料檔總和 < 1 MB） |
| 穩定 | 任一資料檔載入失敗，其他圖層照常運作並顯示提示 |
| 程式 | TypeScript strict；單檔 < 300 行；一個圖層一個檔案 |
| 部署 | GitHub Pages，push main 自動部署 |

## 7. 視覺規範

- 深色底；介面近單色（灰階）＋**單一重點色青色**；警示用紅、注意用琥珀。資料本身（海溫色階）不受此限
- 數字一律等寬字體；面板用細線框與四角標記，不用大面積霓虹與陰影
- 不用 emoji，圖示一律 inline SVG
- 介面中文，欄位標籤可加小字英文（例：航速 SOG）

## 8. 技術架構

```
NOAA ──Python ETL──► public/data/*.json/png
                          │
               DataSource 介面（src/data）──► 之後換成 API + PostgreSQL
                          │
   layers/  sst · currents · fleet · buoys · forecast
   sim/     fleet.worker（位置、事件） · seed
                          │
   MapLibre 底圖 + deck.gl（MapboxOverlay）
                          │
   hud/     KPI · 詳情卡 · 事件流 · 時間軸 · 效能 · 圖層開關
   store.ts（Zustand：圖層開關、選中船、時間、數量）
```

| 決策 | 選擇 | 理由 |
|---|---|---|
| 底圖 | MapLibre | 開源、不需 token、無用量計費 |
| 大量圖層 | deck.gl | WebGL 批次繪製，10 萬點級距 |
| 洋流 | Canvas 粒子拖尾 | 效果成熟、成本低 |
| 模擬 | Web Worker＋Float32Array 傳輸 | 主執行緒不卡；二進位資料免序列化 |
| 狀態 | Zustand | 跨元件共用且避免全樹重繪 |
| 樣式 | CSS 變數＋CSS Modules | 細調線框與光暈，比工具類 class 短 |
| 投影 | 麥卡托 | 地球儀投影與 deck.gl 的相容性未驗證，不冒險 |
| 資料 | 預先烘焙的靜態檔 | 無後端可部署；換 API 只改 DataSource |
